# Deploy Natural Oils to Render

## Before deploying
- This service uses SQLite at `data/natural-oils.db`. Keep the persistent disk mounted at `/opt/render/project/src/data` so records survive restarts and deployments.
- Render's persistent disk requires a paid web-service plan. Do not deploy production customer data to an ephemeral filesystem.
- Set `ADMIN_EMAIL` and a unique strong `ADMIN_PASSWORD` in Render's Environment settings.
- Generate a 32-byte encryption key and enter 64 hexadecimal characters as `DATA_ENCRYPTION_KEY`. Example locally: `openssl rand -hex 32`. Store it in a password manager and never change it after customer data is saved, or existing encrypted fields cannot be decrypted.
- `JWT_SECRET` is generated by the Render blueprint. Keep it private.

## Steps
1. Extract the ZIP and create a private GitHub repository.
2. Upload the contents of the `natural-oils-portal` folder to the repository root (including `render.yaml`).
3. In Render, choose **New + → Blueprint**, connect the private repository, and apply the blueprint.
4. In the Render service's Environment settings, set `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `DATA_ENCRYPTION_KEY`. Never put these in GitHub.
5. Deploy and open the generated `https://...onrender.com` URL. Test customer tracking and admin login with dummy data first.
6. Configure secure off-platform backups for the SQLite database and keep the encryption key backed up separately.

## Limitations before real production use
The portal currently creates an internal E-Way Bill data draft, not an official government E-Way Bill. A live carrier API is not configured. Before processing real customer data, verify CSRF protections, account recovery, backups/restore, logging and monitoring, privacy notice/retention policy, and legal/tax document fields.
